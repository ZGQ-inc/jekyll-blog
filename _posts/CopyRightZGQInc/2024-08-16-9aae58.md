记录一次玩机填坑记录：
感谢 Wesen（兼我前对象）送我一台**三星 Note 4（安卓 6.0.1）**作为七夕礼物。
这台机子是我自己挑的，十年前的一代机皇，如今在闲鱼 60 块钱就能拿下。我虽然用了 10 年三星，但其实并不经常换手机（甚至从安卓 4.4 直接跳到了 8.0）。所以一方面我想看看安卓 6 系时代的三星长什么样，另一方面也想探究一下这个上古系统放到现在还能干点啥。*(其实我本来是打算拿来看本子涩图的...咳，我什么都没说)*

昨天下午刚收到，型号 `SM-N9109W`（国行电信 4G 双卡双待版），3+16G 规格。好在卖家已经刷好了 TWRP 和 Magisk Root，省下了我一大笔折腾当年内核漏洞去 Root 的时间。

![三星 Note 4 截图](/assets/images/2024-08/photo_76@19-08-2026_22-15-32.jpg)

**关于软件生态与折腾填坑：**
众所周知，安卓 6.0.1 的 API 版本为 23。我看了下我主力机里，竟然还有 40% 的应用最低支持 API 小于等于 23（包括 Clash Meta、某透明代理、TG，甚至三星应用商店最新版）。说明大部分软件还没完全放弃这款远古机型，他真我哭。

但在使用中，立刻就碰到了两个**老设备通病：系统证书过期 & WebView 版本过低。**

1.  **SSL/TLS 握手失败与证书过期**
    我在导入订阅节点和更新 F-Droid 软件库时疯狂报错。一看就是系统的 X.509 根证书由于年代久远过期了。
    我尝试手动把 Let’s Encrypt 的新证书安装到用户证书列表，毫无反应（系统内核优先验证自带的旧证书）。**解决办法：** 好在已经 Root，我直接从新手机里把系统证书文件拷出来，用管理器覆盖到 Note 4 的 `/system/etc/security/cacerts` 目录下，重启后网络请求全部恢复正常。
2.  **内置网页浏览器内核 (WebView) 远古**
    系统自带的 WebView 竟然还是极度古老的 `v55.0`。别说网页渲染错位，连最基础的 Cloudflare 人机验证盾都过不去。
    **解决办法：** 去 APKMirror 找最后一个支持 API 23 的 WebView 版本（版本号 `106.0`），下载覆盖安装，问题解决。

**总结：** 安卓 6 系系统目前的可用性至少还能维持在中上水平，虽然感觉也快被淘汰了，但至少不像我那台只能当纯 MP4 用的安卓 4.1 系统 Note 2。
